1

ติดตั้ง Node.js

เครื่องคุณยังไม่มี Node ซึ่งเป็นตัวรันเครื่องมือแปลงโค้ด ติดตั้งครั้งเดียวใช้ได้ตลอด

  1. เปิด nodejs.org กดปุ่มดาวน์โหลดฝั่งซ้ายที่เขียนว่า LTS
  2. เปิดไฟล์ .pkg ที่ดาวน์โหลดมา กด Continue ไปเรื่อยๆ จนจบ
  3. เปิดแอป Terminal (กด ⌘+Space พิมพ์ terminal) แล้วรันคำสั่งนี้เพื่อตรวจ
node -v
npm -v

ต้องขึ้นเลขเวอร์ชันทั้งสองบรรทัด เช่น v22.14.0 และ 10.9.2 ถ้าขึ้น command not found ให้ปิด Terminal แล้วเปิดใหม่

ติดตั้งไลบรารีของโปรเจกต์

cd ~/Desktop/supplier-bidding/app
npm install

ใช้เวลา 1–2 นาที จะมีโฟลเดอร์ node_modules เพิ่มขึ้นมา ถ้ามีคำเตือนสีเหลือง (warn) ไม่เป็นไร ข้ามได้

สร้างโปรเจกต์ Supabase

  1. เปิด supabase.com → Start your project → สมัครด้วย GitHub หรืออีเมล
  2. กด New project ตั้งชื่อ cjx-bidding
  3. ตั้ง Database Password แล้วเก็บไว้ในที่ปลอดภัย (ใช้ตอนต่อฐานข้อมูลตรง)
  4. Region เลือก Southeast Asia (Singapore) — สำคัญ เพราะใกล้ไทยที่สุด
  5. กด Create แล้วรอประมาณ 2 นาที
ห้ามเลือก region อื่น ถ้าเลือกอเมริกา/ยุโรป การกดหยอดราคาจะหน่วงขึ้นเห็นได้ชัด และย้าย region ทีหลังไม่ได้ ต้องสร้างโปรเจกต์ใหม่

ติดตั้งฐานข้อมูล — วางครั้งเดียวจบ

ใช้ไฟล์รวม 00_all_in_one.sql (ตาราง + RLS + ฟังก์ชัน + ที่เก็บไฟล์ อยู่ในไฟล์เดียว) วิธีคัดลอกที่ไม่มีตกหล่น ให้รันคำสั่งนี้ใน Terminal — ไฟล์ทั้งไฟล์จะเข้าคลิปบอร์ดทันที

cat ~/Desktop/supplier-bidding/app/supabase/00_all_in_one.sql | pbcopy
  1. Supabase → SQL Editor → New query → กด ⌘V
  2. คลิกที่พื้นที่ว่างในหน้าต่างหนึ่งครั้ง เพื่อไม่ให้มีข้อความถูกเลือกค้างไว้
  3. กด Run → ต้องขึ้น Success. No rows returned
สาเหตุอันดับหนึ่งของ error syntax error at or near "suppliers" คือ Supabase จะรันเฉพาะข้อความที่ถูกเลือก ถ้ามี selection ค้างอยู่ในหน้าต่าง หรือคัดลอกมาไม่ครบไฟล์ — ใช้คำสั่ง pbcopy ด้านบนแล้วคลิกที่ว่างก่อนกด Run จะไม่เจอปัญหานี้
ไฟล์นี้รันซ้ำได้ เพราะมันลบโครงเดิมทิ้งก่อนสร้างใหม่ ถ้าติดตั้งพลาดครึ่งทางให้รันใหม่ทั้งไฟล์ได้เลย แต่ห้ามรันหลังเริ่มใช้งานจริง เพราะข้อมูลประมูลจะหายทั้งหมด (ถ้าต้องการรันแยกทีละส่วน ไฟล์ 01–04 ยังอยู่ในโฟลเดอร์เดิม)

สร้างผู้ใช้

เมนู Authentication → Users → Add user → Create new user

  1. สร้าง 1 บัญชีสำหรับฝ่ายจัดซื้อ และ 1 บัญชีต่อ 1 ซัพพลายเออร์ (เริ่มด้วย 3 ราย)
  2. กรอกอีเมล + รหัสผ่าน และ ติ๊ก Auto Confirm User ทุกครั้ง
  3. จำอีเมลที่ใช้ให้ครบ — ขั้นถัดไปอ้างอิงจากอีเมล ไม่ต้องคัดลอก UID
natthawut.yut@cjmart.co.th
ฝ่ายจัดซื้อกลาง
chatnapa.ton@cjmart.co.th
Buum Company (V-1001)
passara.rat@cjmart.co.th
Amm Company (V-1002)
saksit.sai@cjmart.co.th
Sanddy Company (V-1003)
ถ้าไม่ติ๊ก Auto Confirm จะเข้าสู่ระบบไม่ได้และขึ้นว่าอีเมลหรือรหัสผ่านไม่ถูกต้อง ซึ่งเป็นปัญหาที่เจอบ่อยที่สุด
รหัสที่คุณตั้งให้ ผู้ขายต้องเปลี่ยนเองก่อนใช้งาน — ระบบบังคับให้เปลี่ยนตอนเข้าครั้งแรก และฝั่งฐานข้อมูลจะปฏิเสธการยื่นราคาจนกว่าจะเปลี่ยน เพราะถ้าไม่บังคับ ฝ่ายจัดซื้อที่รู้รหัสจะเข้าไปยื่นราคาแทนผู้ขายได้ · ส่งรหัสชั่วคราวทางโทรศัพท์หรือ LINE อย่าส่งในอีเมลฉบับเดียวกับลิงก์เข้าระบบ

ถ้าขึ้น error เรื่อง profiles_id_fkey หมายถึงอีเมลในไฟล์ไม่ตรงกับผู้ใช้ที่สร้างไว้ ตอนนี้ไฟล์จะขึ้นข้อความไทยบอกชัดว่าอีเมลไหนหาไม่เจอ — แก้อีเมล 4 บรรทัดบนสุดของไฟล์ให้ตรง แล้วรันใหม่

ตรวจก่อนเปิดใช้จริง

ทำครั้งเดียวก่อนเชิญซัพพลายเออร์เข้าระบบ

ติ๊กไปทีละข้อ ข้อที่ 6–7 สำคัญที่สุด เพราะถ้าพลาดจะเสียส่วนต่างราคาทุกงาน

วิธีเปิดใช้ทดสอบข้อ 6–7 เพิ่มบรรทัด window.supabase = supabase ท้ายไฟล์ src/lib/supabase.js ชั่วคราว ทดสอบเสร็จลบออกแล้ว push ใหม่ ก่อนเปิดใช้จริง
รหัสผ่าน

ตั้งรหัสใหม่ให้ผู้ใช้ เมื่ออีเมลใช้ไม่ได้

อีเมลในตัวของ Supabase free tier ใช้ทำงานจริงไม่ได้ — ส่งได้ไม่กี่ฉบับต่อชั่วโมง และมักไม่ตอบกลับ (ปุ่มลืมรหัสผ่านจะขึ้น HTTP 504) ช่วงติดตั้งจึงควรตั้งรหัสให้ตรงๆ จาก SQL แล้วค่อยต่อ SMTP ภายนอกทีหลังเมื่อต้องการให้ผู้ขายรีเซ็ตรหัสเองได้

วิธีที่ 1 — กดจากในเว็บ (แนะนำ ใช้ประจำวัน)

ติดตั้งครั้งเดียวด้วยไฟล์นี้ แล้วหลังจากนั้นฝ่ายจัดซื้อกดตั้งรหัสให้ผู้ขายได้เองจากเมนู ผู้ใช้และผู้ขาย ไม่ต้องแตะ SQL และไม่ต้องพึ่งอีเมลอีก

cat ~/Desktop/supplier-bidding/app/supabase/07_admin.sql | pbcopy
  1. วางใน SQL Editor แล้ว Run (ครั้งเดียว)
  2. เข้าเว็บด้วยบัญชีฝ่ายจัดซื้อ → เมนู ผู้ใช้และผู้ขาย
  3. กด ตั้งรหัสใหม่ ที่บรรทัดของผู้ขาย → ระบบสุ่มรหัสให้ เช่น CJx-KdmRxs-472 กดคัดลอกแล้วส่งทาง LINE
  4. ผู้ขายเข้าด้วยรหัสนั้น แล้วระบบบังคับให้ตั้งรหัสของตัวเองทันที
ข้อจำกัดที่ตั้งใจใส่ — ตั้งได้เฉพาะบัญชีผู้ขาย บัญชีฝ่ายจัดซื้อตั้งรหัสให้กันเองไม่ได้ (ลดความเสียหายถ้าบัญชีผู้ดูแลถูกยึด) และทุกครั้งที่กดจะถูกบันทึกไว้ในตาราง admin_actions

วิธีที่ 2 — ตั้งรหัสจาก SQL (ใช้กับบัญชีฝ่ายจัดซื้อ)

cat ~/Desktop/supplier-bidding/app/supabase/06_reset_password.sql | pbcopy
  1. วางใน SQL Editor แล้วแก้ 2 บรรทัดบนสุด: อีเมลของคนนั้น และรหัสชั่วคราวที่ต้องการ
  2. กด Run → ใช้รหัสใหม่เข้าสู่ระบบได้เลย
  3. ในไฟล์มีตัวช่วยอีก 4 แบบ (ปิดคอมเมนต์ไว้): ตั้งรหัสเดียวกันให้ทุกคน · ปลดเงื่อนไขบังคับเปลี่ยนรหัส · บังคับให้คนใดคนหนึ่งเปลี่ยนใหม่ · ดูสถานะผู้ใช้ทั้งหมด

สคริปต์นี้เขียนรหัสที่เข้ารหัส bcrypt ลง auth.users ตรงๆ ซึ่งเป็นวิธีเดียวกับที่ Supabase ใช้ จึงเข้าสู่ระบบได้ปกติ · ไม่มีการเก็บรหัสเป็นข้อความธรรมดาที่ไหน

วิธีที่ 3 — ลบผู้ใช้แล้วสร้างใหม่

Authentication → Users → ลบผู้ใช้ → Add user ใส่รหัสที่ต้องการ + ติ๊ก Auto Confirm → แล้วรัน 05_seed.sql อีกครั้งเพื่อผูกโปรไฟล์กลับ

ใช้ได้เฉพาะช่วงยังไม่มีข้อมูลจริง — ถ้ามีใบเสนอราคาของผู้ใช้นั้นอยู่แล้ว การลบจะติด foreign key ให้ใช้วิธีที่ 1 แทน

ถ้าต้องการให้ผู้ขายกด “ลืมรหัสผ่าน” เองได้ (ทำภายหลัง)

  1. สมัคร resend.com (ฟรี 3,000 ฉบับ/เดือน) → สร้าง API key → ยืนยันโดเมนผู้ส่ง
  2. Supabase → Project Settings → Authentication → SMTP Settings → เปิด Custom SMTP
  3. Host smtp.resend.com · Port 465 · User resend · Password = API key
  4. Sender email ใช้โดเมนที่ยืนยันแล้ว เช่น noreply@bidding.cjmart.co.th

ต้องให้ IT เพิ่ม SPF/DKIM ของโดเมนด้วย ไม่งั้นอีเมลจะเข้า junk

ทำครั้งเดียว กับ ทำทุกครั้งที่แก้

สิ่งที่ตั้งไว้แล้วไม่ต้องทำซ้ำ — ขั้น 1–11 ในคู่มือนี้ทำครั้งเดียวตลอดอายุระบบ

สิ่งที่ทำทำเมื่อไร
ติดตั้ง Node · สร้าง Supabase · รัน SQL · สร้างผู้ใช้ · สร้าง repo GitHub · ต่อ Cloudflare · ผูกโดเมน ครั้งเดียว ไม่ต้องทำซ้ำอีก
แก้ไฟล์ใน src แล้ว git push ทุกครั้งที่แก้หน้าเว็บ — Cloudflare build ใหม่เองอัตโนมัติ ~1 นาที ไม่ต้องเข้าหน้า Cloudflare
วาง SQL ใน SQL Editorเฉพาะตอนแก้กติกา — มีผลทันที ไม่ต้อง deploy
แก้ข้อมูลใน Table Editorเฉพาะตอนเพิ่มผู้ขาย/ผู้ใช้ — มีผลทันที
แก้ Environment variables ใน Cloudflareเฉพาะตอนย้ายโปรเจกต์ Supabase — ต้องกด Retry deployment ค่าจึงมีผล
ของที่ไม่เคยหายไปตอนแก้ — ฐานข้อมูล ผู้ใช้ ไฟล์ที่อัปโหลด ประวัติการประมูล repo GitHub และการตั้งค่า Cloudflare ทั้งหมด การ deploy ใหม่แค่เปลี่ยนไฟล์หน้าเว็บเท่านั้น
ข้อควรรู้ — ตอน npm run dev ในเครื่อง มันต่อ Supabase ตัวเดียวกับของจริง ทดสอบอะไรจะกระทบข้อมูลจริง ถ้าอยากแยก ให้สร้างโปรเจกต์ Supabase ตัวที่สองเป็นชุดทดสอบ แล้วสลับค่าใน .env
แบบ 1 · แก้หน้าเว็บ

ข้อความ สี ขนาด เปอร์เซ็นต์ปุ่ม เพิ่ม/ลดช่องในฟอร์ม

  1. แก้ไฟล์ในโฟลเดอร์ app/src
  2. ทดสอบในเครื่อง npm run dev
  3. ส่งขึ้น GitHub 3 คำสั่ง (ด้านล่าง)
  4. Cloudflare build ใหม่เองอัตโนมัติ ~1 นาที
แบบ 2 · แก้กติกา

ใครเห็นราคาเมื่อไร กติกาค้อน รูปแบบเลขที่งาน เงื่อนไขการยื่น

  1. แก้ไฟล์ใน app/supabase/
  2. คัดลอกเฉพาะฟังก์ชันที่แก้ ไปวางใน SQL Editor แล้ว Run
  3. มีผลทันที ไม่ต้อง deploy หน้าเว็บ
  4. push ขึ้น GitHub ด้วย เพื่อไม่ให้ไฟล์กับของจริงต่างกัน
แบบ 3 · แก้ข้อมูล

เพิ่มบริษัทผู้ขาย เพิ่มผู้ใช้ แก้ชื่อ แก้เลขผู้เสียภาษี ลบงานทดสอบ

  1. Supabase → Table Editor
  2. เลือกตาราง เช่น suppliers แล้วกด Insert row
  3. ผู้ใช้ใหม่: Authentication → Add user ก่อน แล้วเพิ่มแถวใน profiles
  4. ไม่ต้องแตะโค้ดเลย

กดบันทึกรหัสผ่านแล้วค้าง / ขึ้นว่าไม่ตอบกลับใน 12 วินาที auth lock ของ supabase ถูกจับค้าง — เกิดจาก 2 อย่าง: (1) เรียก auth ซ้อนใน onAuthStateChange (2) ตอน npm run dev ทุกครั้งที่แก้ไฟล์ HMR สร้าง GoTrueClient ตัวใหม่ ทำให้มีหลายตัวแย่ง lock กัน อัปเดตโค้ดชุดล่าสุด (client เป็น singleton บน globalThis แล้ว + ใช้ client แยกตอนตรวจรหัสเดิม) แล้ว กด ⌘⇧R รีเฟรชแบบล้างแคช หรือหยุด npm run dev แล้วสั่งใหม่ — HMR อย่างเดียวไม่พอ เพราะ client ตัวเก่ายังอยู่ในหน้าเดิม
